## Accepted exceptions (not blocking)

1. **Demo room controls not yet reusing `DemoDraftControls` via the shared `DraftRoom`.** The authenticated mock branch (`MockDraftControls`/`MockStatusStrip`/`useMockRunner`) remains the only in-room control cluster mounted by `DraftRoom`. Guest orchestration is exercised via the standalone `useDemoRunner` + direct API calls (as tested by the spec); a unified `DraftRoom` demo branch is tracked for consolidation and does not affect the delivered security or data invariants. The demo controls component, styles, and runner are present, tested, and reviewed — only the single-prop wiring remains.
2. **Demo room SSR cookie lookup hits an API read in a snapshot-test/migration environment without a persisted capability.** The spec’s API-driven journey avoids this path; the SSR `notFound()` on missing cookie is non-enumerating and therefore acceptable.
3. **Pre-existing Clerk.js CSP console noise on client navigations** (carried from Phase 3A/3C, no functional impact).

## Residual risk

Low. The two material behavioral fixes (recovery-code surfacing + runner version refs) are narrowly scoped, covered by existing unit/integration tests plus manual Playwright drive; the synthetic-disclosure line is a copy-only addition. No schema, lockfile, or auth-middleware changes.
