# Demo dataset attribution and labeling

Status: Phase 1 — this document is the source of truth for what is real vs.
fabricated in `data/demo/*.json`, referenced from `/data-sources` and
`/methodology` (BUILD_SPEC.md section 20) and from every API response that
serves this data (`meta.demoData: true`).

## What is real

- **Team names, cities, conferences, divisions, and abbreviations** (30
  real NBA teams) are public facts.
- **Player names, current team, and eligible positions** for the 210
  non-filler entries in `players.json` are public facts about real NBA
  players, reflecting the generator's (`data/demo/generate.py`) knowledge
  cutoff of approximately January 2026. Roster composition changes
  constantly (trades, signings, injuries) — this snapshot is **not**
  verified against any live source and may not match every transaction
  since that cutoff. Treat team/position assignments as illustrative, not
  authoritative.

## What is entirely fabricated

Everything else, with no exception:

- Every statistic in `player_season_stats.json` — games played, minutes,
  points, rebounds, assists, steals, blocks, turnovers, field goals,
  free throws, three-pointers, for every season and every player,
  including the 210 real players. None of it is a real player's real
  career output. It is generated by a seeded random-number generator
  shaped only by a coarse archetype label (star/starter/rotation/
  breakout/decline/rookie/filler) to look plausible, not to be accurate.
- Every ADP (average draft position) value in `adp_observations.json`,
  attributed to two fictional sources (`demo-adp-source-a`,
  `demo-adp-source-b`). These are not real market data from any real
  fantasy platform.
- Every entry in `news_signals.json` (injury/trade/starter-change/role-up/
  role-down) is a synthetic test fixture, explicitly labeled as such in
  its own `rationale` text. None reports a real event.
- Every entry in `projection_overrides_seed.json` is a synthetic test
  fixture for exercising the admin override workflow, explicitly labeled
  in its `rationale` text.
- All downstream baseline projections computed from this data (Phase 1's
  weighted-historical-baseline engine) are therefore fabricated
  end-to-end and must never be presented as real 2026–27 NBA fantasy
  projections. Every UI surface and API response that touches this data
  carries a persistent `DEMO — SYNTHETIC DATA` label.

## Approximated / synthetic personal data

- **Date of birth**: no real player's real birthdate is used. Each real
  player's synthetic `dob` calibrates only the **year** to their real
  approximate age/experience tier at generation time (rough buckets:
  "young" ≈ early-career, "prime" ≈ established, "veteran" ≈ 30+); the
  month and day are entirely random. This exists solely to make
  age-range filtering demonstrable — it is not a claim about anyone's
  actual birthdate.
- No real player's real height, weight, birth country, or any other
  personal attribute is used; those fields are simply left unpopulated
  in the demo dataset.

## Status labeling policy (why some entries are fully synthetic people)

`Availability` includes `SUSPENDED` and `UNSIGNED`. Attaching a
fabricated `SUSPENDED` status to a real, named person is a materially
different kind of claim than a fabricated stat line — it implies a real
disciplinary event that did not happen. To avoid that entirely:

- **No real player in this dataset is ever assigned `SUSPENDED` or
  `UNSIGNED` status.** Both statuses are used only on the 20 clearly
  synthetic filler players below.
- `ACTIVE` and `INJURED` are used on real players. Both are common,
  constantly-changing, unremarkable real-world statuses, and every
  record carries an explicit fabricated-data / demo-snapshot label, so
  this does not assert anything as a current real-world fact.

### Synthetic filler players

20 entries in `players.json` have `isSyntheticFiller: true` and a
generic, non-distinctive placeholder name (drawn from common first/last
name word lists, not targeting or resembling any specific real person,
living or retired) — `data/demo/generate.py`'s `FILLER_FIRST`/
`FILLER_LAST` lists and `filler_specs`. These exist purely to:

1. demonstrate the `SUSPENDED` status (2 entries) and `UNSIGNED` status
   (3 entries, with no team) without attaching either to a real person;
2. round out team bench depth for a more realistic-feeling pool size (15
   additional entries).

Identify every synthetic filler player programmatically via
`isSyntheticFiller: true` in `players.json`, or by `archetype: "filler"`.

## Images

No real player or team photos or logos are used anywhere in DraftCourt.
Every player/team image reference resolves to an initials-and-team-color
fallback rendered client-side — there is no image asset pipeline in
Phase 1 at all. This sidesteps the licensing review BUILD_SPEC.md section
20 requires before any real photo/logo asset could be used.

## Determinism and reproducibility

`data/demo/generate.py` is seeded (`SEED = 20260820`) and every timestamp
in its output is a fixed literal (`GENERATED_AT`, not wall-clock time).
Re-running it reproduces byte-identical output — verified by
`python3 data/demo/generate.py --verify` (runs generation twice into
isolated temp directories and diffs checksums) and by
`services/analytics/tests/test_demo_dataset.py`. `data/demo/manifest.json`
records the seed, generation timestamp, and a sha256 checksum of every
generated file.
